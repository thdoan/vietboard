# Phase 4 Manual Test Steps

> One test at a time. Report back after each step with PASS or FAIL + any console errors.
> After **every reload**, verify **all** of these states on the reloaded player's screen:
> - **Board:** committed tiles + any preview tiles (with correct `t1`/`t2` styling)
> - **Racks:** player's rack (with `.` dots for tiles in preview), opponent's rack
> - **Game Info:** last score, total score, tiles left in bag
> - **History:** words played table
> - **Play Buttons:** disabled when it's not the player's turn
> - **Clear/Shuffle:** says "Clear" when board has ≥1 preview tile, "Shuffle" otherwise

---

## Pre-requisites
- Two browser tabs (Player A = **Host**, Player B = **Guest**)
- Open DevTools console on both
- Coin flip decides first turn — the player whose turn it is performs all actions

---

## Test 1: Preview tiles survive own reload

### Steps
1. Active player drags a tile to board (e.g., `c7_7`).
2. Wait **at least 300ms**.
3. **Same player** reloads.
4. Verify **all states** listed above.

### Expected
- Preview tile on `c7_7` with `t1` styling.
- Rack shows `.` where tile came from.
- All other states intact.
- No console errors.

---

## Test 2: Opponent sees preview after active player reloads

### Steps
1. Active player drags a tile to `c7_7`.
2. Wait 300ms.
3. **Same player** reloads.
4. After reconnect, check **opponent's** screen. Verify **all states**.

### Expected
- Opponent sees preview on `c7_7` with `t2` styling.
- Actual letter shown, not blank.
- Opponent's own state unchanged.

---

## Test 3: Guest reloads and sees Host's preview

### Steps
1. **Host** drags a tile to `c8_8` (must be Host's turn).
2. Wait 300ms.
3. **Guest** reloads.
4. After reconnect, check **Guest's** screen. Verify **all states**.

### Expected
- Guest sees Host's preview on `c8_8` with `t2` styling.
- Shows actual letter.
- Host's screen unchanged (`t1` styling).

---

## Test 4: Rack correctly shows dots for tiles in preview

### Steps
1. Active player drags **2** different tiles to board.
2. Check that player's rack.

### Expected
- Exactly 2 cells show `.`.
- After reload, dots remain in correct positions.

---

## Test 5: Clear button derives from preview state

### Steps
1. Active player drags a tile to board.
2. Observe **Clear** button.
3. Click **Clear** to return tile to rack.
4. Observe button again.

### Expected
- "Clear" when preview exists → "Shuffle" after clearing.
- Works before and after reload.

---

## Test 6: Ghost drag system remains untouched

### Steps
1. Active player starts dragging a tile but **does not drop**.
2. Check opponent's screen.

### Expected
- Opponent sees ghost indicator.
- Tile appears normally on drop.
- No drag broadcast errors.

---

## Test 7: Play move commits correctly (regression)

### Steps
1. Active player forms a valid word on board.
2. Click **Play**.
3. Observe both screens. Verify **all states**.

### Expected
- Scores applied.
- Tiles committed.
- History updated.
- Turn swaps.
- DB version increments cleanly.

---

## Test 8: Drag-churn then rack return (regression)

### Steps
1. Active player drags tile to `c7_7`.
2. Drags same tile to `c8_7`.
3. Drags tile back to rack.
4. **Opponent** reloads.
5. Verify **all states** on opponent's screen.

### Expected
- No stale previews on `c7_7` or `c8_7`.
- Board matches committed state only.

---

## Test 9: Shuffle after clearing preview tiles

### Steps
1. Active player drags a tile to board.
2. Observe that button now shows **Clear** (preview exists).
3. Click **Clear** to return tile to rack.
4. Observe that button now shows **Shuffle**.
5. Click **Shuffle**.
6. Observe rack.

### Expected
- Rack tiles shuffle.
- No preview tiles remain on board.
- Board shows only committed tiles.
- Button remains **Shuffle** after shuffle completes.

---

## Test 10: Full state preservation after both players reload

### Steps
1. Play several moves so both players have scores and history.
2. Active player drags a preview tile to board.
3. Wait 300ms.
4. **Both players reload** (one at a time, e.g. Host first, then Guest).
5. After each reload, verify **all states** on that player's screen.

### Expected
- After both reloads, both players see identical committed board, correct preview tiles, correct racks with dots, correct scores, correct history, correct turn indicator, correct button states.
